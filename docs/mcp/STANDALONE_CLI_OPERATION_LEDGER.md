In Slice 2, the runtime worker families (`ProcessSupervisor`, `tty`, `EventSink`, `transfer_store`, `file_paths`, `ssh_ops`, `sftp_ops`, `boundary_ops`, `openvpn_ops`, `caddy_ops`) were extracted in `scp-core`, delegated from `src-tauri`, and exposed in 9 direct `scpctl` runtime subcommands (`openvpn detect`, `openvpn start --foreground`, `boundary targets search`, `boundary auth`, `caddy start --foreground`, `server tunnel start`, `server ssh --interactive`, `scp upload`, `scp download`). In Slice 3, the pure `.scpbak` archive/preview/fingerprint/reference engine (`scp-core::backup`) and transactional config/server/credential/sync-push/RDP mutations (`scp-core::config_ops`) are shared with `src-tauri` and exposed across 14 new CLI commands (`completion`, `server upsert`, `server delete`, `server credentials set/clear`, `server rdp`, `config save/patch`, `config secret set/clear`, `config sync push`, `settings patch`, `settings export`, `settings import`, totaling `31` CLI schemas). In Slice 4, `scpctl mcp serve --stdio` expands to all **41** `Capability::Runtime` registry operations (`11` permitted under default `read-only` policy, `15` with `file-transfer`, `41` with `allow-local-policy` and all `4` policy categories), live `stdio-policy.json` reload with fail-closed corruption handling, bounded concurrency/cancellation/framing/write-timeout transport controls, and SDK/Client/Inspector CLI verification, while **4** operations remain explicitly excluded as `CAPABILITY_UNAVAILABLE` (`server_rdp_start`, `config_sync_pull`, `config_git_pull`, `config_git_push`). In Slice 5, release packaging (`scripts/package-scpctl.mjs`), checksum-verified prefix installation (`scripts/install-scpctl.sh`), `Dockerfile.cli`, `.github/workflows/standalone-cli.yml`, `STANDALONE_CLI_AGENT_GUIDE.md`, runnable `examples/standalone-cli/{shell,stdio-mcp}-agent-workflow.mjs`, and `dbus-run-session` GUI-free Secret-Service-absent smoke checks are verified on Linux `x86_64`. Existing desktop handlers and HTTP policy remain unchanged via shared re-exports, delegations, and host-neutral `OperationError::for_host`.

## Profile and platform decisions and Linux Slice 0 spike evidence

Use the plan's canonical private profile directory and one OS-backed exclusive owner lease for all profile-backed commands, including queries. Acquire profile lease before metadata/recovery, then the process maintenance gate; never acquire these in reverse. Keep a stable random credential namespace outside portable settings and recover before any loader/cache/runtime side effect. Reject the desktop profile (including canonicalized symlink/`..` aliases); do not infer desktop paths or copy its identity. Root workspace contains only independent packages; desktop remains an explicitly excluded package with its existing lockfile, build script, and target paths. It consumes the shared registry through a path dependency. `experiments/cli-stdio-slice0` holds the disposable Slice 0 platform and `stdio` verification binary, excluded from the root workspace.
